# 事故响应流程（Incident Response）

> 版本：v1.0 | 日期：2026-03-18

---

## 1. 事故等级定义

| 级别 | 影响范围 | 示例 | 响应时间 | 解决时间 |
|------|---------|------|---------|---------|
| P0 | 全站不可用 / 数据丢失风险 | 登录全部失败、白屏 | 15min | 2h |
| P1 | 核心功能不可用 | 用户无法支付、管理员无法操作 | 30min | 4h |
| P2 | 次要功能异常 | 部分报表数据异常、导出失败 | 2h | 24h |
| P3 | 轻微缺陷 | UI 错位、文案错误 | 1工作日 | 下次迭代 |

---

## 2. 响应流程

```
发现告警/用户反馈
        │
        ▼
    5min 内认领（On-call）
        │
        ▼
    评估影响范围和等级（P0-P3）
        │
        ├── P0/P1 → 立即拉事故群，通知相关方（技术负责人、产品、运营）
        │
        ▼
    快速定位根因
    （查 Sentry 错误 → 查监控指标 → 查最近部署）
        │
        ▼
    止损操作（回滚 / 降级 / 切流量）
        │
        ▼
    根本修复（提 Hotfix PR）
        │
        ▼
    验证恢复正常
        │
        ▼
    事故复盘（24h 内，P0/P1 必做）
```

---

## 3. 快速定位步骤

### Step 1：确认影响面
```bash
# 查看 Sentry 错误量趋势
# 查看监控大盘（错误率、响应时间、成功率）
# 确认影响的用户范围/功能范围
```

### Step 2：排查最近变更
```bash
# 查看最近部署记录
git log --oneline main..HEAD -20

# 查看最近 1h 的错误日志
# Sentry → Issues → 按时间过滤
```

### Step 3：前端常见排查
```bash
# 1. 打开浏览器控制台，看 JS 错误
# 2. 看 Network 请求是否异常（4xx/5xx）
# 3. 确认 CDN/静态资源是否正常加载
# 4. 检查 token 相关问题（401 重定向循环）
```

---

## 4. 止损手段

| 问题 | 止损方案 | 负责人 |
|------|---------|--------|
| 新版本问题 | 立即回滚到上一版本 | DevOps |
| CDN 问题 | 切换 CDN 节点 / 回源 | DevOps |
| 接口 500 | 前端降级展示（fallback UI）| 前端 |
| Token 问题 | 强制全局退出登录 | 后端 + 前端 |
| 数据展示异常 | 暂时关闭受影响功能入口 | 前端 + 产品 |

## 5. 事故复盘模板

```markdown
# 事故复盘报告

**事故 ID：** INC-2026-001
**日期：** 2026-03-18
**持续时间：** 14:23 - 15:47（84分钟）
**等级：** P1
**影响用户：** ~3,200 人（约15%）

## 时间线
- 14:23 - 监控告警触发（登录成功率跌至 32%）
- 14:28 - On-call 认领，拉事故群
- 14:35 - 定位到根因（Token 刷新接口返回格式变更）
- 14:52 - 前端补丁 PR 合并
- 15:47 - 部署完成，监控恢复正常

## 根因分析
后端 v2.3.1 变更了 `/auth/refresh` 响应格式（accessToken → access_token），
前端未感知，导致 token 刷新失败，用户被强制退出。

## 直接原因
接口契约变更未提前通知前端，缺少契约测试。

## 根本原因（5 Whys）
1. 为什么 Token 刷新失败？→ 字段名变更
2. 为什么字段名变更未被发现？→ 无接口契约测试
3. 为什么没有契约测试？→ 未建立前后端契约测试机制
4. 为什么未建立？→ 团队认为手动联调足够

## 改进措施
| 措施 | 负责人 | 截止日期 |
|------|--------|---------|
| 引入 Pact 契约测试 | @前端 + @后端 | 2026-04-01 |
| API 变更通知流程 | @Tech Lead | 2026-03-25 |
| 增加登录成功率监控告警 | @DevOps | 2026-03-22 |

## 结论
此次事故可避免，需通过规范 API 版本管理和契约测试加以预防。
```
