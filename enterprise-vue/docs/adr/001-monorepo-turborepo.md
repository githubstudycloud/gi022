# ADR-001: 采用 pnpm Workspaces + Turborepo 作为 Monorepo 方案

> 日期：2026-03-18 | 状态：已采纳 | 作者：架构组

---

## 背景

随着企业前端应用数量增长（主应用、管理后台、移动端），各应用间存在大量重复的工具函数、类型定义和 UI 组件。多仓库模式导致：
- 代码同步困难，各应用版本不一致
- 依赖重复安装，本地磁盘占用大
- 共享库发布流程繁琐

## 决策

采用 **pnpm Workspaces + Turborepo** 构建 Monorepo 工程。

## 备选方案对比

| 方案 | 优点 | 缺点 | 是否采用 |
|------|------|------|---------|
| pnpm + Turborepo | 增量构建、任务并行、依赖去重 | 学习成本 | ✅ 采纳 |
| Nx | 功能强大、插件丰富 | 重量级，配置复杂 | ❌ |
| Lerna + yarn | 历史悠久，文档多 | 较慢，yarn 依赖不如 pnpm | ❌ |
| Rush | 微软出品，适合超大型 | 配置繁琐，学习曲线高 | ❌ |
| 多仓库 | 各自独立，灵活 | 共享困难，版本不一致 | ❌ |

## 理由

1. **pnpm** 依赖硬链接节省磁盘，严格的依赖解析避免幽灵依赖
2. **Turborepo** 智能缓存（本地+远程），增量构建提速 70%+
3. 两者配合是 2025 年社区最主流的前端 Monorepo 最佳实践
4. 迁移成本低，pnpm workspace 配置简单

## 影响

- 所有前端项目统一在一个仓库管理
- 本地开发需要安装 pnpm（≥9.0）
- CI 需要配置 Turborepo 远程缓存（可选）
