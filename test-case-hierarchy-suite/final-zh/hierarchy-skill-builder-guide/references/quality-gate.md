# 质量门槛

## 触发质量

定稿前检查这些点：

- `description` 同时说明了 skill 做什么，以及何时使用。
- 触发示例已经被 frontmatter 覆盖，而不是只藏在正文里。
- skill 的范围足够窄，能被重复复用。

## 渐进披露

检查这些内容边界：

- `SKILL.md` 里应该主要是工作流，而不是巨大的领域表格。
- 所有大矩阵和模板都应放在 `references/`。
- 每一个 reference 文件都必须在 `SKILL.md` 里被显式提到。
- 不要保留没有实际用途的资源目录。

## 参考样板复用

当你拿现有本地 skill 当模板时：

- 只有结构匹配时才复制结构
- 新领域的术语必须保持准确
- 不要机械搬运不适用的示例标题
- 要确认新 skill 在不加载旧 skill 的情况下也能独立成立

## 仓库内专项复核

对这个仓库里的层级类 skill，额外检查：

- 使用的源文档是解释当前任务所需的最小集合
- 硬性的父子规则没有丢
- 除非确有必要，不要把右侧详情行为和树结构规则写成一锅
- 只有在确实增加价值时才引用校验脚本或 fixture 文件

## 最终检查

收尾时跑完这些动作：

1. 删掉 TODO 和占位语句。
2. 把 skill 从头到尾读一遍，假设使用者对上下文一无所知。
3. 确认 `agents/openai.yaml` 仍然和 skill 范围一致。
4. 对 skill 目录运行 `quick_validate.py`。
