# 测试树场景需求文档

## 1. 文档目标

本文档用于把当前“左侧树 + 右侧详情”的实际业务场景整理成统一、可执行、可校验的需求描述，为后续设计文档、技能封装、接口设计和测试代码提供统一依据。

## 2. 业务目标

系统需要用一棵复杂测试树统一承载以下对象及其关系：

- 空间
- 产品
- 基线版本
- 容器版本
- 执行版本
- 用例容器
- 测试场景
- 目录
- 特性
- 基线用例
- 执行用例

系统需要支持：

- 树层级管理
- 节点详情展示和编辑
- 100+ 动态字段扩展
- 节点创建、修改、删除、移动
- 特性改目录
- 目录改特性
- 多接口组合支撑复杂右侧详情区

## 3. 术语统一

当前按以下口径统一：

- `测试版本 = 执行版本`
- `测试项 = 目录`
- `容器版本` 在结构能力上等价于 `基线版本`
- `特性` 与 `目录` 等价，可以互改 `type`

## 4. 树节点核心字段

每个树节点至少具备以下核心字段：

| 字段 | 说明 |
| --- | --- |
| `longIdPath` | 长 ID 路径，使用 `/` 分隔 |
| `shortId` | 短 ID |
| `currentLevelId` | 当前层级 ID，应与 `longIdPath` 最后一段一致 |
| `type` | 节点类型 |
| `name` | 节点名称 |
| `number` | 节点编号 |

此外还支持：

- 100+ 扩展字段
- 类型特有字段，例如状态、排序、来源、模式标记、统计字段
- 右侧详情区的显示/编辑字段

## 5. 节点类型

| 中文名 | 建议类型值 |
| --- | --- |
| 空间 | `space` |
| 产品 | `product` |
| 基线版本 | `baseline_version` |
| 容器版本 | `container_version` |
| 执行版本 | `execution_version` |
| 用例容器 | `case_container` |
| 测试场景 | `test_scene` |
| 目录 | `directory` |
| 特性 | `feature` |
| 基线用例 | `baseline_case` |
| 执行用例 | `execution_case` |

## 6. 层级关系需求

### 6.1 顶层关系

- 空间下可以直接挂：
  - 产品
  - 基线版本
  - 容器版本

### 6.2 产品下关系

- 产品下可以直接挂：
  - 基线版本
  - 容器版本

### 6.3 基线版本与容器版本关系

- 基线版本和容器版本在结构上按同一套规则处理
- 两者的直接下级都只允许：
  - 一个 `用例容器`
  - 零个或多个并列的 `执行版本`

因此，基线版本和容器版本下：

- 不允许直接挂目录
- 不允许直接挂特性
- 不允许直接挂用例
- 不允许直接挂场景

### 6.4 基线版本与容器版本下的用例容器

- 基线版本的 `用例容器` 下是基线侧内容
- 容器版本的 `用例容器` 下也按基线侧内容处理
- 其下可以挂：
  - 目录
  - 特性

但不允许直接挂用例。

用例必须建在目录或特性下面。

### 6.5 执行版本下关系

- 执行版本的直接下级只允许一个 `用例容器`
- 执行版本不能直接挂场景
- 执行版本不能直接挂目录、特性、用例

执行版本下存在两种组织形态：

1. 容器直挂内容形态
2. 场景分组形态

但执行版本一旦选择了其中一种组织形态，就不能再切换。

### 6.6 执行版本的容器直挂内容形态

```text
execution_version
└─ case_container
   ├─ directory
   │  └─ execution_case
   └─ feature
      └─ execution_case
```

约束如下：

- `case_container` 下可直接挂目录和特性
- `case_container` 下不能直接挂执行用例
- 用例必须建在目录或特性下
- 此形态下不能再新增场景

### 6.7 执行版本的场景分组形态

```text
execution_version
└─ case_container
   ├─ test_scene
   │  ├─ directory
   │  │  └─ execution_case
   │  └─ feature
   │     └─ execution_case
   └─ test_scene
```

约束如下：

- `case_container` 下一旦挂了场景
- 后续目录、特性、执行用例都只能建在场景下
- `case_container` 下不能再直接建目录、特性、执行用例
- `test_scene` 下也不能直接建用例
- 用例必须建在场景下的目录或特性下面

### 6.8 场景约束

- `test_scene` 下不能再挂 `case_container`
- `test_scene` 下可以挂：
  - 目录
  - 特性

但不能直接挂执行用例。

### 6.9 目录与特性约束

- `directory` 与 `feature` 等价
- 两者可以互改 `type`
- 两者都可以继续嵌套：
  - 目录
  - 特性
  - 用例

目录与特性互转时，默认只改 `type`，节点 ID 与路径保持不变。

## 7. 右侧详情需求

右侧详情区至少需要支持：

- 查看和编辑当前节点详情
- 按当前节点上下文显示子节点或统计信息
- 基于节点类型展示不同字段组
- 动态字段渲染和校验

右侧详情区必须能够：

- 根据 `type` 切换字段布局
- 根据上下文区分基线用例与执行用例
- 根据执行版本当前组织形态控制创建入口
- 支持 100+ 扩展字段动态展示

## 8. 动态字段需求

系统存在大量可扩展字段，因此不能把所有字段都平铺到固定结构中。

必须支持：

- 固定核心字段 + 扩展字段的混合模型
- 不同节点类型拥有不同字段定义
- 新增字段不要求改动所有节点类型代码
- 右侧详情区按字段定义动态渲染
- 查询接口按需返回精简字段或全量字段

## 9. 操作需求

系统需要支持：

- 查询树
- 查询节点详情
- 创建节点
- 修改节点
- 删除节点
- 移动节点
- 调整排序
- 特性改目录
- 目录改特性

校验重点包括：

- 父子关系是否合法
- 基线版本/容器版本/执行版本下是否存在唯一用例容器
- 执行版本是否混用两种组织形态
- 用例容器下是否直接建了用例
- 场景下是否直接建了用例
- 用例类型是否和版本上下文一致
- `longIdPath` 是否和父子关系一致

## 10. 非功能需求

- 树结构规则需要可配置、可测试
- 文档、skill、测试代码要共用同一套术语
- 校验逻辑要能脱离 UI 单独运行
- 后续新增节点类型时，优先通过规则扩展而不是重写全量逻辑

## 11. 当前已确认结论

当前这几个点已经明确，不再视为待确认项：

1. `测试版本 = 执行版本`
2. `测试项 = 目录`
3. `容器版本` 分支按基线侧处理
4. 基线版本、容器版本、执行版本都只能直接挂一个用例容器
5. 基线版本、容器版本的用例容器里都是基线用例
6. 执行版本有两种组织形态，但创建后不能切换
7. 用例容器和场景下面都不能直接建用例
8. 特性和目录等价，可互改 `type`
