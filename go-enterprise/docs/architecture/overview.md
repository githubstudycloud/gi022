## 1. 系统定位

go-enterprise 是一个面向中大型企业的 Go 微服务框架模板，目标是：

- **标准化**：统一技术栈、项目结构、编码规范
- **可扩展**：模块解耦，按需引入
- **可观测**：开箱即用的日志、追踪、指标
- **高可用**：限流、熔断、优雅停机

## 3. 分层架构（每个服务内部）

```
┌──────────────────────────────────────────────────┐
│  Handler Layer（HTTP / gRPC）                     │  ← 请求解析、参数校验、响应格式化
├──────────────────────────────────────────────────┤
│  Service Layer（业务逻辑）                         │  ← 业务规则、编排、事务
├──────────────────────────────────────────────────┤
│  Domain Layer（领域模型）                          │  ← 实体、值对象、领域规则（无依赖）
├──────────────────────────────────────────────────┤
│  Repository Layer（数据访问）                      │  ← DB/Cache/MQ 操作
└──────────────────────────────────────────────────┘
```

依赖方向：**Handler → Service → Domain ← Repository**（Domain 不依赖任何外层）

## 4. 目录规范

```
apps/{service-name}/
├── cmd/
│   └── main.go              # 程序入口，组装依赖
├── internal/
│   ├── domain/              # 领域模型（纯 Go，无框架依赖）
│   ├── repository/          # 数据访问层
│   ├── service/             # 业务逻辑层
│   ├── handler/             # HTTP/gRPC 处理层
│   └── dto/                 # 对外数据传输对象（可选）
├── config/
│   ├── app.yaml             # 开发环境配置
│   └── app.prod.yaml        # 生产环境覆盖配置
└── migrations/              # 数据库迁移脚本（Flyway/golang-migrate）
```

## 5. 技术选型

| 类别 | 选型 | 理由 |
|------|------|------|
| Web 框架 | Gin | 性能优异，生态成熟 |
| ORM | GORM | 功能完整，支持迁移 |
| 缓存 | go-redis/v9 | 官方维护，支持集群 |
| 消息队列 | Sarama (Kafka) | 高吞吐，可靠 |
| 配置管理 | Viper | 多源、热更新 |
| 日志 | Uber Zap | 高性能结构化日志 |
| 分布式追踪 | OpenTelemetry | 行业标准，与厂商无关 |
| 指标 | Prometheus | 行业标准 |
| 测试 | Go 标准库 + testify | 简洁、够用 |
