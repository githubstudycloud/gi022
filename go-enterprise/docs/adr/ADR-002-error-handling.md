# ADR-002: 统一错误码体系

**状态**: Accepted
**日期**: 2026-03-18

---

## 背景

微服务对外暴露 API，需要统一错误响应格式，方便客户端处理和问题定位。

## 决策

采用三层错误体系：

```
HTTP 状态码（传输层）
    └── 业务错误码 code（应用层）
            └── 原始 error（调试层，仅日志记录）
```

**响应格式**：
```json
{
  "code": 1004,
  "message": "resource not found",
  "trace_id": "abc123"
}
```

**错误码分段**：

| 范围 | 用途 |
|------|------|
| 0 | 成功 |
| 1000-1999 | 通用错误（参数、权限等） |
| 2000-2999 | 用户服务业务错误 |
| 3000-3999 | 订单服务业务错误 |
| 5000-5999 | 系统内部错误 |

**原则**：
- 业务错误码在各服务的 `internal/errors/codes.go` 中定义
- 错误不向上层透传技术细节（DB 错误、SQL 语句等）
- 系统错误统一记录完整 stack trace，对外只返回 5000

## 影响

- 前端/客户端需依据 `code` 字段处理逻辑，而非 HTTP 状态码
- 所有 handler 层使用 `middleware.Fail(c, err)` 统一返回
