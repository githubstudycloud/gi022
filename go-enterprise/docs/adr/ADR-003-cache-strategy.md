# ADR-003: 缓存一致性策略（Cache Aside）

**状态**: Accepted
**日期**: 2026-03-18

---

## 背景

写数据库和写缓存两步操作无法原子完成，需要明确的缓存一致性策略。

## 决策

**采用 Cache Aside（旁路缓存）模式**：

```
读操作：
  1. 先查缓存
  2. 缓存 miss → 查数据库
  3. 将结果回填缓存（TTL 保底）

写操作：
  1. 先写数据库（主操作）
  2. 删除缓存（而非更新）← 关键！
  3. 下次读时自动回填
```

**为什么删除而不是更新缓存？**
- 更新缓存存在并发写竞争（最后一次写可能覆盖更新的数据库值）
- 删除是幂等操作，更安全

**TTL 设置原则**：
- 热点数据：5~30 分钟
- 列表数据：1~5 分钟（变更频繁）
- 用户会话：和 Token 有效期一致

**缓存穿透防护**：
- 数据库查询为空时，缓存空值（TTL 30s）
- 使用 Bloom Filter 过滤明显无效 ID（可选，高流量场景）

## 影响

- 写操作后缓存有短暂不一致窗口（可接受）
- 高并发下可能有缓存击穿风险，使用 `GetOrSet` 的单飞模式（singleflight）缓解
